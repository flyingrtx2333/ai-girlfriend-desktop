# Agent 实现清单

目标：实现完整 Agent 功能，复刻用户参考的 Qoder 工作方式。保留 AppKit、低内存与低能耗约束。此清单用于追踪完整目标，不把阶段交付当作完成。

对标来源（2026-11-06 核对）：[桌面版功能](https://docs.qoder.com/qoder/overview)、[任务管理](https://docs.qoder.com/qoder/task-management)、[执行监控](https://docs.qoder.com/qoder/task-monitor)、[审批与隔离](https://docs.qoder.com/qoder/approval-and-sandbox)、[扩展](https://docs.qoder.com/qoder/connectors)。用户前面的界面参考作为布局依据；用户已确认对标桌面 Agent，完整 IDE 编辑器不纳入范围。

## 现有基线

v0.8.2 已有原生聊天、BYOK 模型配置、MiniMax 语音、离线声学唤醒、桌宠互动、闲置屏幕评论。尚无执行任务的工具循环，不具备文件编辑、终端执行或持久任务系统。

## 实施顺序

1. 原生 Agent 数据模型、任务存储、工具循环、文件与终端工具、联网工具和审批。
2. 接入原生任务界面、执行记录与产物；真实模型跑通一项文件任务、审批和停止。
3. 项目与任务完整管理、变更审阅/撤回/Git、记忆与索引、上下文压缩。
4. 浏览器与桌面工具、附件、Skills/MCP/Hooks/插件、自定义 Agent 与协作。
5. 定时任务、其他扩展与远程接入，完成全部能力逐项审计；原目标保持 active，直到实际证据充分。

## 验证约定

优先验证真实业务流程、真实模型和实际落盘结果。只做当前风险需要的最少检查；构建或模拟响应不能替代 Agent 效果验收。现有个人配置、Token、聊天历史和未发送草稿必须保留。测试使用独立临时项目，不把私人文件、截图或凭据写入 Git。

## 附件基础设施与早期验证

`evidence/agent/documents-gu9wiT/document-report.json` 只验格式和存储，不当作 AI 对话验收：使用 python-docx、openpyxl、python-pptx 创建并独立回读公开文件，原生解析确认 Word 段落/表格、工作表顺序、数值/格式/公式缓存和重排后的幻灯片；不把缺少缓存的公式结果当作已计算。原生生成的 PDF 与实际图片通过本机 OCR 读出金额及队列，扫描页按需识别，UTF-16 DTD 在解析前拒绝。
