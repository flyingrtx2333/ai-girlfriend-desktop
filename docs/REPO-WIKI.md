# Wiki 规划

在「记录 → Wiki」选择简体中文或 English，点击「规划」编辑生成结构。文档目录按规划中的父子页面组织，也可按实际标题或路径搜索；「旧版」保留原 `.bluefatfish/wiki/` 文档。

本阶段为开发候选，尚未替换日常应用。首轮真实模型验收在8192／512配置下反复读取和整理上下文，30次额度耗尽，未发布页面；上下文修复仍需真实模型复验。文件与窗口检查使用实际项目文档的手工导入副本，不作为模型生成结果。

配置保存到项目的 `.bluefatfish/repowiki/wiki_plan.yaml`。自己的配置不存在时读取 `.qoder/repowiki/wiki_plan.yaml`；编辑后保存到自己的路径，兼容来源保持原字节。保存前校验 YAML 与父子结构，检测外部修改，原配置另存到应用的私有备份目录。重新载入、关闭、退出应用或开始生成前会处理未保存的规划草稿。

```yaml
version: 1
repowiki:
  template: architecture
  notes:
    - text: 根据实际源码说明实现，并引用已读行。
  documents:
    - title: 项目总览
      goal: 说明实际功能与入口
      hints: [README.md]
    - title: 开发流程
      goal: 说明构建与验证方式
      parent: 项目总览
      hints: [docs/DEVELOPMENT.md]
```

`template` 支持 `architecture`、`product_requirement`。`notes` 可使用文字或 `text` 对象。每页需要唯一 `title` 和非空 `goal`，可选 `parent`、`hints`、文字 `template`；`hints` 支持文字或文字数组。父页面须存在且不能形成循环，第一页必须是根页面。单份配置最多64KB、100页；省略 `documents` 时，由生成任务先核对实际项目索引，再通过 `plan_wiki` 提交一次页面结构。已确定的结构不可在同一生成任务中替换。

生成任务保存当时的规划、配置哈希、分支与语言。后续共享配置变更不改变该任务；Git 分支变化会阻止旧任务继续读写和发布。同一工作区、分支、语言的活动生成任务会复用，不重复启动。

Wiki 使用实际文件哈希、已读行范围和写后回读记录提供当前页面进度，保留原始历史与完整用户要求，仅选择近期完整工具交互进入模型上下文，不再调用模型反复整理 Wiki 过程记录。每次源码或页面读取最多30行，并按约400估算 token 保留完整行；返回 `next_offset` 供续读。超长单行会明确拒绝，不能把未回读内容视为完成。

新版文档写入 `.bluefatfish/wiki/.generated/<分支哈希>/<语言>/<任务编号>/`，仅能写当前规划的精确路径，不能执行命令、联网或修改源码。覆盖已有草稿需当前文件哈希。页面写后须完整回读，源码行引用须对应本任务实际读过、当前哈希一致的文件。最后重新核对项目索引、实际 `finish_task` 记录与完整计划，再更新该分支和语言的私有发布清单；旧发布版本和失败草稿均保留。

旧版顶层文档不迁移、不删除，也不会与隐藏的新生成目录混排。中文尚无新版发布时会沿用旧版读取，英文尚无发布时显示空目录。用户手工编辑后的已发布页面会标为「已编辑」，源码索引变化标为「需更新」。

更多菜单的「自动引用 Wiki」默认开启，按工作区保存并适用于该工作区各语言与分支。关闭后，普通任务不再获得 Wiki 提示，`project_wiki` 不进入工具定义或加载结果，先前取得的工具调用在执行时也会重新核对开关。Wiki 自身生成仍可核对先前文档，窗口阅读及用户显式加入的文档资料继续可用；已有对话记录不删除。知识卡片的自动引用设置保持独立。设置使用应用私有的 `wiki/settings.json`，保存核对原版本，配置无效或路径不安全时停止自动引用并保留原文件。

在 Wiki 更多菜单中，可将当前语言导出到 `.bluefatfish/repowiki/<zh|en>/content/`，元数据保存在相邻的 `meta/repowiki-metadata.json`。导出内容是实际磁盘文件；未保存草稿须先保存。Wiki 内的页面、图片、源码链接会随目标目录重新定位，保留片段和行号；代码示例不改写，原文编码、字节标记和换行沿用原件，图片原字节保留。只打包当前 Wiki 目录内直接引用的普通资源，项目源码仍引用项目内原件。

将这些文件加入 Git 后，其他副本可从同一目录导入。确认框显示当前分支、语言、页数和实际内容预览；共享文件经人工修改或新增页面会进入新预览。导入重新核对来源、当前版本和工作区，任何预览后的修改都会要求重新预览。新文档写入独立目录，发布仅替换当前分支、当前语言的清单，旧根目录不覆盖。缺少可核对源码记录的导入显示「待核对」，不标为模型已生成。

替换前把当前文档、实际人工修改和引用资源保存到应用私有版本目录；「恢复 Wiki 版本」先选择并预览，再发布为一个新版本。恢复同样检查文件和当前版本是否改变，保留原件。再次导出只覆盖本应用已有记录且未被外部修改的文件，遇到新页面、外部修改或符号链接时停止；写入失败会尝试恢复已写入且仍与本次字节一致的文件，保留备份。

每次最多1000页，文档总量32MB，单页512KB且解析文本最多300000个 UTF-16 单元；资源最多1000份、单份20MB、总量64MB。导入导出使用版本1的 `bluefatfish.repo-wiki` 格式；尚不支持 Qoder 私有元数据格式。旧版文档与版本2的生成清单保持可读，导入与恢复使用版本3清单，不创建伪造的模型生成任务。

兼容文件中的 `knowledgecard` 配置随原 YAML 保留，本阶段尚未把其写作说明接入知识卡片生成。Wiki 的增量维护、专门的暂停恢复界面、知识卡片合并传递与云端团队拉取仍在完整开发范围内。
