# Repo Wiki

在「记录 → Wiki」选择简体中文或 English，点击「规划」编辑生成结构。文档目录按规划中的父子页面组织，也可按实际标题或路径搜索；「旧版」保留原 `.bluefatfish/wiki/` 文档。

本阶段为开发候选，尚未替换日常应用。首轮真实模型验收在8192／512配置下反复读取和整理上下文，30次额度耗尽，未发布页面；上下文修复仍需真实模型复验。文件与窗口检查使用实际项目文档的手工导入副本，不作为模型生成结果。

配置保存到项目的 `.bluefatfish/repowiki/wiki_plan.yaml`。自己的配置不存在时读取 `.qoder/repowiki/wiki_plan.yaml`；编辑后保存到自己的路径，兼容来源保持原字节。保存前校验 YAML 与父子结构，检测外部修改，原配置另存到应用的私有备份目录。重新载入、关闭、退出应用或开始生成前会处理未保存的规划草稿。

```yaml
version: 1
repowiki:
  template: architecture
  notes:
    - text: 根据实际源码说明实现，并引用已读行。
  documents:
    - title: 项目总览
      goal: 说明实际功能与入口
      hints: [README.md]
    - title: 开发流程
      goal: 说明构建与验证方式
      parent: 项目总览
      hints: [docs/DEVELOPMENT.md]
knowledgecard:
  notes:
    - 重点核对模块职责、实际约定和依赖
```

`template` 支持 `architecture`、`product_requirement`。`notes` 可使用文字或 `text` 对象。每页需要唯一 `title` 和非空 `goal`，可选 `parent`、`hints`、文字 `template`；`hints` 支持文字或文字数组。父页面须存在且不能形成循环，第一页必须是根页面。单份配置最多64KB、100页；省略 `documents` 时，由生成任务先核对实际项目索引，再通过 `plan_wiki` 提交一次页面结构。已确定的结构不可在同一生成任务中替换。

生成任务保存当时的规划、配置哈希、分支与语言。后续共享配置变更不改变该任务；Git 分支变化会阻止旧任务继续读写和发布。同一工作区、分支、语言的活动生成任务会复用，不重复启动。

当前分支和语言尚无 Wiki 时，按钮显示「生成 Wiki 与卡片」。首次生成先核对项目索引，再创建互相关联的 Wiki 和卡片任务，沿用同一源码版本、分支、语言及当时的配置；两者准备完成后才进入现有运行队列。已有卡片会保留其版本校验与用户补充，不忽略独立卡片任务；存在活动卡片生成时先要求暂停。同一范围的并发点击共用一次准备，不重复创建任务。Wiki 页底部的「知识卡片」打开相应语言的卡片窗口，可查看实际卡片与生成任务。

停止 Wiki 生成任务会同时停止配套卡片，保留原消息、读取记录、草稿和已完成部分；继续沿用两个原任务，只启动尚未完成的部分。重开应用后同样读取保存的关联，不自动重放模型请求；完成调用已发生但发布中断时，先按原有事实与版本保护重试原生发布。源码、分支、项目目录身份、卡片原版本或 Wiki 发布版本已变化时要求重新核对或生成，不能把两个不同源码版本的结果当作共同完成。首次生成失败后重新生成会建立新的一对任务，旧记录与两份草稿保留。停止全部任务也会取消尚在进行的原生准备。

已有 Wiki（含手工导入或旧版文档）之后，Wiki 生成、重新生成及增量维护保持独立；卡片按自身入口维护。首次协同生成仍由两个原生发布流程分别核对，不因另一任务完成而伪造发布成功。真实模型验收的 Wiki 单项入口继续只创建 Wiki，原 Wiki 额度不会自动用于配套卡片。

`knowledgecard.notes` 单独约束知识卡片的内容组织，支持文字或 `text` 对象，最多30项、每项4000字节；只配置 `knowledgecard` 时也须保留 `version: 1`。每次生成卡片前读取并冻结说明，沿 `read_project_knowledge(configuration:true)` 的 `next_content_offset` 续读，完整读取后才允许保存草稿。说明不是源码事实或工具批准，仍需核对实际源码。配置无效时停止创建新任务并保留原文件；运行中的任务与旧历史不受后续配置变化影响。Wiki 的模型规划读取不包含卡片说明，两类要求独立。

Wiki 窗口底部的生成按钮随任务状态显示「暂停生成」「继续生成」或「生成 Wiki」。暂停沿用运行时的取消机制，保留原任务、冻结规划、源码读取记录与文档草稿；继续启动同一任务，已读取源码、索引或已发布版本变化时要求重新生成。重启后留下的待开始任务同样可继续。暂停不会丢弃当前文档编辑；继续前会处理未保存文档和规划。

更多菜单的「重新生成 Wiki」先确认当前分支、语言和规划页数，再核对确认期间这些范围、配置或发布版本是否变化。确认有效后暂停当前生成，创建独立任务和草稿目录，采用当前配置重新规划／生成。原任务、失败记录、草稿和已发布页面保留；新任务通过完整校验后才替换发布清单。存在未保存文档时须先保存，发布中的任务暂不能暂停或重新生成。

「增量更新」比较已发布 Wiki 的 Git 提交基线与当前提交，先显示分支、语言、两个提交和实际差异，再确认开始。仅支持 Git 仓库；需要先提交项目修改。新发布的 Wiki 在项目源码已提交时保存基线；旧清单缺少基线时须重新生成，不猜测历史提交。同一提交不重复更新；差异超过200个文件或128KB时须分批更新或重新生成。项目、分支、目录身份、提交、源码或 Wiki 在确认期间变化时停止，原文保留。

更新冻结原文档规划，把当前页面和附件复制到新的独立草稿。模型先分段读取完整提交差异，再结合实际代码核对直接和间接影响。每段按约400估算 token 保留完整字符，沿 `next_offset` 续读；连续读取范围合并保存，不因长中文差异累积而丢失进度。源码哈希未变的页面由应用保留，不伪造本次模型读取或写入；源码变化但原文仍准确时，须实际读取当前引用行、完整回读页面，再调用 `plan_wiki(confirm_page:路径, expected_hash:哈希)` 确认保留。事实变化的页面须修改并完整回读。未读完差异、未经核对的页面、失效引用或附件变化均不能发布；更新期间原页面被人工编辑或新增页面时，同样保留原文和本次草稿。没有文档需要改写时可用真实差异审阅调用作为完成依据，不制造无意义写入。

「自动更新」「自动导出」默认关闭，按工作区和语言独立保存在应用私有 Wiki 设置中。开启前确认实际影响。自动更新在应用运行期间观察 Git 提交，复用上述增量流程；绑定原任务、项目目录身份及权限，按当前分支和语言处理。相同提交不重复启动，暂停或失败的同一提交须手动检查后继续；存在人工修改的 Wiki 时先提示手动审阅。关闭开关停止后续触发，已开始的任务仍可在生成按钮暂停。应用重开后恢复明确启用的观察，不自动重放暂停或失败任务。自动更新会使用所选任务的模型并产生相应费用。

自动导出在生成、增量更新或导入发布后，把当前语言写入项目共享目录，沿用下述外部修改与覆盖保护。导出失败不撤销已经发布的 Wiki，窗口与任务日志保留可处理的错误。两个自动开关、自动引用和其他语言设置共同核对完整设置版本，旧设置不能覆盖新修改；旧引用设置格式保持可读。

Wiki 使用实际文件哈希、已读行范围和写后回读记录提供当前页面进度，保留原始历史与完整用户要求，仅选择近期完整工具交互进入模型上下文，不再调用模型反复整理 Wiki 过程记录。每次源码或页面读取最多30行，并按约400估算 token 保留完整行；返回 `next_offset` 供续读。超长单行会明确拒绝，不能把未回读内容视为完成。

新版文档写入 `.bluefatfish/wiki/.generated/<分支哈希>/<语言>/<任务编号>/`，仅能写当前规划的精确路径，不能执行命令、联网或修改源码。覆盖已有草稿需当前文件哈希。页面写后须完整回读，源码行引用须对应本任务实际读过、当前哈希一致的文件。最后重新核对项目索引、实际 `finish_task` 记录与完整计划，再更新该分支和语言的私有发布清单；旧发布版本和失败草稿均保留。

旧版顶层文档不迁移、不删除，也不会与隐藏的新生成目录混排。中文尚无新版发布时会沿用旧版读取，英文尚无发布时显示空目录。用户手工编辑后的已发布页面会标为「已编辑」，源码索引变化标为「需更新」。

更多菜单的「自动引用 Wiki」默认开启，按工作区保存并适用于该工作区各语言与分支。关闭后，普通任务不再获得 Wiki 提示，`project_wiki` 不进入工具定义或加载结果，先前取得的工具调用在执行时也会重新核对开关。Wiki 自身生成仍可核对先前文档，窗口阅读及用户显式加入的文档资料继续可用；已有对话记录不删除。知识卡片的自动引用设置保持独立。设置使用应用私有的 `wiki/settings.json`，保存核对原版本，配置无效或路径不安全时停止自动引用并保留原文件。

在普通 Agent 任务中使用 `/knowledge-edit` 明确指定 Wiki、知识卡片或两者。Wiki 编辑先用 `read_project_wiki` 选择当前分支和语言的页面，按页读取目标正文及哈希，再用 `read_file` 核对源码；`edit_project_wiki` 只替换完整读过且唯一的片段，每次单独确认。保留原编码、字节标记、换行、其他页面和另一语言，写前归档当前完整版本，写后回读。文件、目录身份、分支、发布版本、权限或源码引用变化时拒绝写入；问答模式不可编辑。明确编辑时仍可读 Wiki，自动引用保持关闭。手工编辑的 Wiki 标为「已编辑」，自动更新不会直接覆盖；Wiki 与卡片分别维护，未被指定的内容不联动修改。

在 Wiki 更多菜单中，可将当前语言导出到 `.bluefatfish/repowiki/<zh|en>/content/`，元数据保存在相邻的 `meta/repowiki-metadata.json`。导出内容是实际磁盘文件；未保存草稿须先保存。Wiki 内的页面、图片、源码链接会随目标目录重新定位，保留片段和行号；代码示例不改写，原文编码、字节标记和换行沿用原件，图片原字节保留。只打包当前 Wiki 目录内直接引用的普通资源，项目源码仍引用项目内原件。

将这些文件加入 Git 后，其他副本可从同一目录导入。确认框显示当前分支、语言、页数和实际内容预览；共享文件经人工修改或新增页面会进入新预览。导入重新核对来源、当前版本和工作区，任何预览后的修改都会要求重新预览。新文档写入独立目录，发布仅替换当前分支、当前语言的清单，旧根目录不覆盖。缺少可核对源码记录的导入显示「待核对」，不标为模型已生成。

替换前把当前文档、实际人工修改和引用资源保存到应用私有版本目录；「恢复 Wiki 版本」先选择并预览，再发布为一个新版本。恢复同样检查文件和当前版本是否改变，保留原件。再次导出只覆盖本应用已有记录且未被外部修改的文件，遇到新页面、外部修改或符号链接时停止；写入失败会尝试恢复已写入且仍与本次字节一致的文件，保留备份。

每次最多1000页，文档总量32MB，单页512KB且解析文本最多300000个 UTF-16 单元；资源最多1000份、单份20MB、总量64MB。导入导出使用版本1的 `bluefatfish.repo-wiki` 格式；尚不支持 Qoder 私有元数据格式。旧版文档与版本2的生成清单保持可读，导入与恢复使用版本3清单，不创建伪造的模型生成任务。

知识卡片合并传递与云端团队拉取仍在完整开发范围内。首次协同生成、写作说明、Wiki 编辑及增量更新的真实模型效果须单独验收，文件、Git 和窗口检查不代表模型输出质量已经通过。
